# Security Policy

## Supported Versions

We release updates for the current major version. Security updates are backported when feasible.

| Version | Supported          |
| ------- | ------------------ |
| 2.x     | :white_check_mark: |
| 1.x     | :x:                |

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

If you believe you have found a security vulnerability in this repository, please report it responsibly:

1. **Email** the maintainer (see GitHub profile) with:
   - A description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if any)

2. Allow time for a response before disclosing publicly. We aim to respond within 72 hours.

3. If the vulnerability is accepted, we will work on a fix and coordinate disclosure.

Security vulnerabilities in skills content (e.g., malicious instructions) are treated with high priority. We will remove or fix problematic content and publish an advisory.

## What We Consider a Security Issue

- Malicious or unsafe content in skill instructions
- Vulnerable code examples that could lead to security flaws when used
- Supply chain or dependency issues in tooling (if applicable)

Thank you for helping keep this project safe.
